Drive it all from the API

The console is just a client. Every capability here is a plain HTTP endpoint, so you can run campaigns straight from your dialer, CRM or backend - no UI needed. Base URL is this service; examples use $BASE.
BASE="__BASE__"

Endpoints

Method & pathPurpose
POST/api/callPlace a call or start a run (transfer modes or a drop campaign)
GET/api/run/:idRun status + per-leg outcomes (poll from your system)
POST/api/listSave a reusable named call list; returns its id
GET/api/listsList saved call lists
GET/api/list/registry/:idA saved list's members
DEL/api/list/:idDelete a saved list
POST/api/message?name=Store a named voicemail (raw WAV body); returns its id
GET/api/messagesList named messages
DEL/api/message/:idDelete a named message
GET/api/sf/lists · /api/sf/list/:idSalesforce campaigns and their members
GET/api/log?since=Event timeline (for a dashboard)

Transfer on machine

Call one number; when a machine answers, transfer to a colleague. A human answer is left a short notice.

curl -X POST $BASE/api/call -H 'Content-Type: application/json' -d '{
  "mode": "detect",
  "to": "447700900461",
  "forward": "447700900123"
}'

mode: detect (transfer as soon as a machine is detected) or detect_beep (after the voicemail beep).

Voicemail-drop campaign with human → agent

Dial a whole list. Machines get your recorded/auto message; humans transfer to a live agent over SIP (e.g. Vonage Contact Center) with custom headers for routing and the CRM screen pop.

curl -X POST $BASE/api/call -H 'Content-Type: application/json' -d '{
  "mode": "drop",
  "members": [ { "number": "447700900461", "whoId": "a0X...", "name": "Jane Doe" } ],
  "messageId": "943ae6bc",
  "concurrency": 5,
  "from": "447700900000,447700900001",
  "humanAction": "sip",
  "sipUri": "sip:queue@yourvcc.sip.vonage.com",
  "sipHeaders": { "X-NVM-AgentId": "1234", "X-NVM-RecordId": "{{whoId}}" },
  "resultWebhook": "https://your-system.example.com/vonage-results"
}'

Drop-run options

FieldMeaning
numbers / members / listIdThe list: pasted/CSV text, an array of {number,whoId?,name?}, or a saved list id.
messageIdWhich named message to play into machines. Omit for the default/automatic message.
concurrencySimultaneous calls, 1-10 (default 1). Staggered to respect account calls-per-second. Pace to your available agents.
fromOne caller number, or several (comma-separated / array) to spread the run across a number pool (round-robin). Defaults to the configured number.
humanActionskip (default), forward (to humanForward, a phone number), or sip (to sipUri + sipHeaders).
sipHeadersCustom INVITE headers. Values template per contact: {{whoId}} {{number}} {{name}} {{runId}} {{legId}}.
resultWebhookHTTPS URL - every outcome is POSTed to you (see below).
logToSftrue to also log each outcome to Salesforce (if connected).

Outcome webhook

Set resultWebhook and we POST every call result to your endpoint, then a final run_completed. Keeps your CRM writes on your side.

// per call
{ "event": "call_result", "runId": "ab12cd34", "legId": 0,
  "number": "447700900461", "name": "Jane Doe", "whoId": "a0X...",
  "outcome": "machine_message_dropped", "callUuid": "…", "at": "2026-…Z" }

// when the run ends
{ "event": "run_completed", "runId": "ab12cd34", "total": 500,
  "counts": { "machine_message_dropped": 210, "human_transferred": 60, … } }

Outcomes: machine_message_dropped, machine_transferred, human_transferred, human_skipped, no_answer, busy, failed, transfer_failed.

Saved lists & messages

Save a reusable list (paste or CSV: number,name,salesforceId per line), then run it by listId.

curl -X POST $BASE/api/list -H 'Content-Type: application/json' -d '{
  "name": "Campaign North",
  "numbers": "447700900461,Jane Doe\n447700900462,John Roe"
}'
# -> { "id": "df8c69cb", ... }   then:  "listId": "df8c69cb" in /api/call

Store a per-campaign voicemail (WAV, 16-bit PCM; the console records/encodes it for you):

curl -X POST "$BASE/api/message?name=Campaign%20North" \
  -H 'Content-Type: audio/wav' --data-binary @message.wav
Auth & security. The service authenticates to Vonage with your application's private key (server-side). The console/API sit behind your VCR instance - add your own access control before exposing them. Set VONAGE_SIGNATURE_SECRET to verify Vonage's event webhooks. Full setup, billing and self-host steps are in IMPLEMENTATION.md (Source tab / GitHub).
