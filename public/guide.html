Machine Detect - the full guide

Place calls, let Vonage decide human vs answering machine, and act on it - transfer the live person to an agent, or leave a voicemail. Two ways to use it: the console (point and click) or the API (integrate into your own system).

First, the idea
What it does, in one line each
1

Transfer if machine

Call one number. If a machine answers, transfer the call to a colleague / queue. If a human answers, it just says a short goodbye and hangs up. (Modes detect and detect_beep.)

2

Voicemail drop

Call a whole list of numbers. On a machine, leave a voicemail after the beep and move on. On a human, do what you choose - skip, forward to a person, or transfer to your contact centre over SIP. (Mode drop.)

Part 1
One-time setup

Two minutes. You just tell Vonage which number(s) can make the calls.

1

Link your number(s) to the Application

In the Vonage Dashboard, open your account, go to Applications, open Machine Detect, and under Linked numbers link the number(s) you want to call from. You can link several - the tool can spread a run across all of them.

You can use multiple numbers. In the console's Caller number(s) box (or the API from field) enter several, comma-separated, and calls are spread across them.
2

(For SIP transfer) point your contact centre at a SIP address

If you want live answers routed to your VCC / agents, have the SIP address ready, e.g. sip:queue@yourvcc.sip.vonage.com. You'll paste it in the console or send it as sipUri.

Part 2
Using the console (point and click)

Open the tool at the base URL. Everything is one screen.

1

Pick what happens: the Detection Mode

Top of the form. Choose Transfer as soon as a machine is detected, Transfer after the beep, or Leave a voicemail on a list. (Salesforce is optional - ignore that box unless you use it.)

2

Enter the number(s), the caller ID, and press Call

Transfer modes: enter the Number to call and the Forward to number. Voicemail drop: paste your list of numbers (one per line, CSV allowed: number,name,id) and upload/record the message. Then set Caller number(s) and press Call.

3

Watch it happen

The Event log shows each call live (calling, human/machine detected, transferred, voicemail left). Live listen lets you hear the far side of the call from your browser.

Part 3
Integrate via API (Postman / your system)

Everything the console does is a plain HTTP call. Base URL below - no auth needed to the tool itself.

Base URL:
1

Start a call / run - POST /api/call

One endpoint does everything. Send JSON. Example - a voicemail-drop over a list, humans routed to your SIP agent, results posted to your endpoint:

curl -X POST "$BASE/api/call" -H "Content-Type: application/json" -d '{
  "mode": "drop",
  "numbers": "447700900461,Jane Doe\n447700900462,John Roe",
  "from": "447700900111,447700900112",     // one or many caller IDs
  "concurrency": 5,
  "humanAction": "sip",
  "sipUri": "sip:queue@yourvcc.sip.vonage.com",
  "sipHeaders": { "X-CRM-Id": "{{whoId}}" }, // carried to your VCC screen-pop
  "ringTimeout": 45, "beepTimeout": 45, "agentTimeout": 30,
  "resultWebhook": "https://your-system.example.com/hooks/md"
}'

Returns { "ok": true, "runId": "1a2b3c4d", ... }.

2

The fields you can send

FieldWhat it does
modedetect / detect_beep (transfer if machine) or drop (voicemail campaign).
to, forwardTransfer modes: the number to call + where to send it on a machine.
numbers / membersDrop mode: the list. Text (number,name,id per line) or [{number,name,whoId}].
fromCaller ID - one number, or several comma-separated to spread across a pool.
concurrencyDrop mode: how many calls at once (1-10).
humanActionDrop mode, when a human answers: skip / forward / sip.
humanForward / sipUriWhere live answers go (a phone number, or a SIP address).
sipHeadersCustom SIP headers for your VCC (values support {{whoId}} {{number}} {{name}}).
messageIdDrop mode: which uploaded voicemail to play (see /api/messages).
ringTimeoutRing the person this long with no answer, then hang up. Default 45.
beepTimeoutWait this long for the voicemail beep. Default 45.
agentTimeoutRing the agent this long on a transfer, then give up. Default 45.
resultWebhookYour HTTPS endpoint - one JSON result per callout is POSTed here.

Part 4
The JSON your system receives

Set resultWebhook to your endpoint. We POST one call_result per callout, then one run_completed at the end of a batch. Nothing is written anywhere else.

1

One result per call

{
  "event": "call_result",
  "runId": "1a2b3c4d", "legId": 12,
  "callUuid": "63f61863-4a51-4f6a-bba5-3f6e9a9c1e77",
  "mode": "drop",
  "number": "447700900461", "name": "Jane Doe", "whoId": "00Q5g000004AbCdEAA",
  "from": "447700900111",
  "answeredBy": "human",              // human | machine | none
  "action": "transferred_to_agent",   // voicemail_left | transferred_to_agent | skipped | no_answer | failed
  "transferredTo": { "type": "sip", "destination": "sip:queue@yourvcc.sip.vonage.com" },
  "voicemailMessageId": null,
  "outcome": "human_transferred",
  "timeouts": { "ringSec": 45, "beepSec": 45, "agentSec": 30 },
  "at": "2026-08-26T10:15:20.100Z"
}

The two fields you'll branch on: answeredBy (human / machine / none) and action (what we did).

2

One summary per batch

{
  "event": "run_completed", "runId": "1a2b3c4d", "mode": "drop",
  "total": 250,
  "counts": { "machine_message_dropped": 180, "human_transferred": 42,
              "no_answer": 25, "failed": 3 },
  "at": "2026-08-26T10:32:00.000Z"
}
Your endpoint should reply 2xx quickly - we don't retry, and we time out our POST after 5 seconds so a slow endpoint never holds up dialling.
Part 5
Timeouts & silence handling
1

You control every timeout

ringTimeout = ring the person X seconds then hang up (your "if it's rung for X, drop it"). beepTimeout = wait for the voicemail beep. agentTimeout = ring the agent on a transfer then give up. All optional, all in seconds.

Silence after answer: if a person picks up and says nothing - when an agent is free the call connects and the agent hears it; when the agent is busy we leave the voicemail and hang up; and an unanswered call is dropped after your ringTimeout.
